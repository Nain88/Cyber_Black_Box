# Engineering audit and Docker consolidation — 18 November 2026

Scope: full review of the backend (`cbb/`), web console (`web/`), and deployment (Dockerfile, compose files, lab), followed by fixes, a four-container Docker deployment, a GUI redesign, and automated plus end-to-end verification. Branch: `fyp/docker-audit-gui`.

## 1. Result summary

| Check | Result |
| --- | --- |
| Python test suite (`pytest -q`) | **124 passed** (115 existing + 9 new) |
| Web unit tests (`pnpm --dir web test`) | **10 passed** |
| Web production build (`tsc -b && vite build`) | Passes, no type errors |

The end-to-end test ran against the real four-container stack. It covered:

- first-time setup, login, the CSRF check and rejection of foreign origins
- case creation
- all three Lab attack scenarios run from the `lab` container
- sealing of every observation
- signed PDF, DOCX and JSON reports and the evidence ZIP, signed by the `trust` container
- offline package verification with the deployment public key
- a checkpoint anchored by the witness
- an integrity verification job that returned **VALID**

## 2. Deployment: before and after

**Before**, there were three separate compose files plus a host-side setup:

- `compose.cloud.yml`: 4 containers, needing real TLS certificates and mTLS.
- `compose.virtual.yml`: 1 container.
- `compose.lab.yml`: needed an external Kali VM.

The lab also launched a throwaway container per run through the host Docker CLI. **The image did not build at all**: Debian bookworm no longer ships the `suricata` package. The lab could not work when the app itself ran in a container, because it needed the Docker CLI and listened on loopback.

**After:** one `docker-compose.yml` with **four containers** and no host dependencies.

| Container | Role | Networks |
| --- | --- | --- |
| `db` | PostgreSQL 17 | backend (internal) |
| `app` | API, web console and workers; port 8765 bound to loopback only | frontend, backend, lab |
| `trust` | Isolated Ed25519 signer plus checkpoint witness | backend (internal) |
| `lab` | Attack-simulation sender: fixed scenarios, token-authenticated, targets limited to an allowlist of private addresses | lab (internal) |

Hardening carried over to every container:

- read-only root filesystem
- all Linux capabilities dropped
- `no-new-privileges`
- memory and CPU limits
- healthchecks

`db` and `trust` cannot be reached from the host or from the lab sender. Secrets are generated randomly into `.env` by `Start-Docker.cmd` / `scripts/docker-up.ps1`, and `.env` is git-ignored.

## 3. Defects found and fixed

### Backend

| # | Severity | Defect | Fix |
| --- | --- | --- | --- |
| 1 | Critical | The Docker image failed to build because the `suricata` apt package is unavailable. | Removed it. PCAP analysis with Suricata remains an optional external integration. |
| 2 | Critical | Every signed report failed when the separate signer was used: `CBB-REPORT-v1` was missing from the signer's allowed domains, so every export job failed after 3 retries. | Added the domain, plus a regression test. |
| 3 | High | `cli serve --host 0.0.0.0` refused to start in Virtual Mode, so the image's default command exited immediately. | Container binding is allowed when `CBB_CONTAINER=true`; host publication stays loopback-only. |
| 4 | High | Browsing to `http://localhost:8765` made every POST fail with `ORIGIN_DENIED`, because the configured origin was `127.0.0.1`. | In Virtual Mode, localhost and 127.0.0.1 are now the same origin. Optional `CBB_ALLOWED_ORIGINS` adds others. Tested. |
| 5 | High | The Lab could not run inside Docker: it needed the Docker CLI and socket, and its decoys listened on loopback. | New `cbb/labsender.py` service and an HTTP executor. Decoys bind through `CBB_LAB_BIND`. The old Docker Desktop executor remains for native Windows installs. Tested end to end. |
| 6 | Medium | The Lab run crashed with a `KeyError` when an observation was rejected. | Only accepted receipts are used. |
| 7 | Medium | Live-monitor polling wrote a custody-ledger entry every 5 s per open tab (about 17k a day), slowing verification and export over time. | An entry is written only when the visible result set changes. Tested. |
| 8 | Medium | Re-authentication accepted a reused TOTP code within its 30 s window. | Replay is checked against `last_totp_counter`, as login already does. |
| 9 | Medium | The witness could not be used without manually copying keys between containers. | The `trust` entrypoint pins the signer key into the witness. The app trusts the co-hosted witness on first use (`CBB_WITNESS_AUTO_TRUST`) and records it as **not independent**. |
| 10 | Low | The Docker log never said where the first-time setup token is. | The token is printed in `docker compose logs app` and by the launcher. |
| 11 | Low | The AI assistant could not reach Ollama from inside Docker, because it was loopback-only. | Added an explicit `CBB_OLLAMA_ALLOWED_HOSTS` allowlist; Compose allows only `host.docker.internal`. |
| 12 | Low | Dead Kali-SSH executor in `lab.py`. | Removed. `cbb/kali.py` is kept for its existing tests. |

### Web console

The redesign is described in section 4. The functional bugs fixed were:

- **Unsafe data handling:**
  - Unsafe `JSON.parse` inside render on the Live monitor.
  - Unguarded nested data access that could crash the assistant, integrations, guide, integrity and models pages.
- **Wrong status display:**
  - The severity scale had Informational ranked above Low.
  - About 10 statuses (NEW, OPEN, PROPOSED…) rendered as grey.
  - The integrity banner stayed green on INVALID.
- **Stale or misleading state:**
  - Stale data was shown after switching items.
  - "UTC" date filters actually sent local time.
  - Linux collectors defaulted to the Windows `System` channel.
- **Code-level fixes:**
  - Circular import between `operations.tsx` and `main.tsx`.
  - Possible NaN chart width.
  - Unencoded IDs in links.
  - Hard-coded note avatar.
- **Lab page:** it polled every 2 s even when idle.

## 4. GUI redesign

- **One stylesheet** (`web/src/theme.css`), built on a complete token set: surfaces, text, accent, semantic and severity colours, plus spacing, radius, type scale and shadows. It replaces two conflicting stylesheets that had three overlapping themes and only four variables.
- **Themes:** a professional dark SOC theme by default, with a light theme toggle. Minimum text size is 12 px, colours meet WCAG AA contrast, and there is a single breakpoint system with a working mobile navigation drawer.
- **Navigation:** grouped, collapsible navigation with distinct icons. The breadcrumb shows group › page › record.
- **Overview dashboard:** KPI cards, an evidence-by-source bar chart and an alerts-by-severity donut, drawn in inline SVG with no new dependencies.
- **Readable records:** raw JSON dumps on about 15 screens are replaced with key/value views. Forensic records keep a "Raw JSON" disclosure.
- **Collapsible notices:** long disclaimers collapse to their first sentence. Warnings always stay expanded, and no wording was removed.
- **Accessibility:** tables are denser, with full-row and keyboard-activatable selection. Tabs follow the ARIA pattern, with arrow, Home and End keys.

## 5. Known limitations (documented, not hidden)

- **Witness independence.** The witness is co-hosted with the signer in the `trust` container. It detects rollback and forks, but it is **not** an independent third-party anchor. The console labels it accordingly.
- **Suricata and Zeek** live network capture, Windows Event Log and Npcap collection, and MEGA archive are host-side integrations. They are not part of the Docker stack. The collector agent (`cbb/agent.py`) can still be enrolled from a host.
- **Investigator scoping.** Investigators can search the whole evidence pool, by design per the README; administrators are case-scoped. Review this if strict compartmentalisation is required.
- **Blocking request handlers.** Large artifact and PCAP uploads use `async` handlers that do blocking file and database work. That is acceptable for single-user demos; it should move to a threadpool before multi-user production use.
- **Checkpoint retry with a remote signer.** If the local transaction fails after the signer has recorded a checkpoint sequence, the retry can conflict (HTTP 409). This is rare and needs manual repair; it is documented for future work.
- **Cloud Mode.** `compose.cloud.yml` (TLS/mTLS, Nginx) is kept for reference, but it was not part of this acceptance run.

$t = docker compose -p cbb-smoke exec -T app cat /data/keys/bootstrap.token

docker compose -p cbb-smoke down -v
